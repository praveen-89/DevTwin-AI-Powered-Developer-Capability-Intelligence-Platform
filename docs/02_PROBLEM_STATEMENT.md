# 02. Problem Statement

## The Problem
The software industry lacks an accurate, dynamic, and evidence-backed mechanism for evaluating and understanding a developer's true engineering capabilities over time. 

Current methods for assessing developer skill and engineering behavior are fundamentally flawed:

1. **Static and Self-Reported**: Resumes and LinkedIn profiles represent a static snapshot in time, often self-reported, lacking objective verification of actual applied capability.
2. **Superficial Metrics**: Generic GitHub dashboards focus on volume (e.g., commit counts, "green squares", lines of code) rather than the quality, context, and complexity of the engineering work.
3. **Isolated Testing**: Traditional coding assessments (e.g., LeetCode-style tests) measure algorithmic problem-solving in a vacuum, completely disconnected from real-world engineering behaviors such as architecture design, dependency management, code maintainability, and handling of technical debt.
4. **Lack of Provenance**: When AI tools or generic resume analyzers do attempt to score developers, they operate as "black boxes." They provide a score without a clear, traceable path to the underlying evidence.
5. **Conflation of Skill and Capability**: Existing systems fail to distinguish between knowing a technology (Skill) and effectively applying it in a software project (Capability).

## The Consequence
Because of these limitations, organizations and developers themselves struggle to:
- Accurately identify genuine skill gaps.
- Understand the risks inherent in a developer's current engineering practices.
- Recommend targeted, effective learning interventions.
- Track how learning outcomes translate into improved engineering capabilities.

There is a critical need for a system that can intelligently parse the heterogeneous artifacts of a developer's actual work (source code, commits, architectural patterns, dependency choices) to construct a reliable, evolving, and explainable representation of their capabilities.
